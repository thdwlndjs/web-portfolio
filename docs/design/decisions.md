## C. 사용자가 직접 지적한 실패 패턴

1. 디자인을 **논의하기 시작하는 단계인데** AI가 “확정됐다”며 Codex 구현으로 넘김 → 사용자 정정. 현재도 실험/승인을 엄격히 구별.
2. 사전 레퍼런스 없이 추상적인 A/B/C만 던지는 방식 → 사용자는 **모든 디자인 선택 앞에 실제 레퍼런스** 요구.
3. 추가 프로젝트 미리보기 오른쪽에 제목·설명·버튼까지 중복 → 사용자가 “오른쪽에는 이미지만”이라고 직접 수정.
4. 작은 모바일 썸네일 시안이 실제 화면 정보를 전달하지 못함 → 텍스트 목록 + 탭 확대 방식으로 변경.
5. AI가 원래 합의한 핵심 이력보다 다른 성과를 더 중시해 프로토타입 문구를 교체함 → 왼쪽 3줄을 명확히 고정.
6. 현재 프로토타입의 카피 `채용하세요...`는 사용자가 승인하지 않았음 → 기존 사실과 채용 톤에 맞춰 재검토.
7. `.md`에 무조건 많이 저장하면 토큰과 품질이 개선된다고 과장하지 말 것. 작업별 선택적 조회, 최신 명세 분리, 모호할 때 원문 조회가 핵심.

## E. 현재 별도 의사결정이 필요한 항목

- COLOR: 최종 팔레트/대비/프로젝트 화면 배경과의 조화.
- DETAIL: 경력·교육·수상/학술 실적 섹션의 레이아웃과 상세 카피(원본 확인).
- TYPE METRICS: SUIT 글자 크기·줄간격·굵기·한/영 줄바꿈.
